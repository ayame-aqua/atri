## 1. 本阶段要做成什么样

聊天页增加「按住说话 / 点击开始录音」。你的中文进 Agent，她的 **日语台词** 一边送 GPT-SoVITS，一边译成中文气泡（总纲 §4.3）。TTS **锁定已有 GPT-SoVITS 推理服务**（不走 Edge TTS）。权重已在别的项目炼好，本仓库不训练、不拷贝 ckpt。

延迟目标：**2–4 秒可接受**（识别 + 生成 + 合成/翻译并行），不作为硬失败，但要可测量。按句流式、抢话留给 P5。

因为 P2-A 已过：语音里说的称呼和「记住」的事实，刷新后纯文字再问仍在。不要把本阶段验收写成「语音可用但不承诺跨重启记忆」。

### 1.1 要做

- ASR：浏览器 PCM/WebM → 后端转写
- 转写文本走与 Web 相同的 `Gateway` + `Agent` + `MemoryStore`
- TTS：用 `speech_ja` 调本机 SoVITS；同时把日语译成中文气泡（P1 已有译文则不必再译）
- 固定一个音色，写进 config，本阶段中途不换模型当儿戏
- 识别失败时文字回复「没听清」，不瞎编用户原话
- `chatId` 建议 `web:local` 与语音共用同一会话（同一页里语音只是输入方式）；若拆 `voice:local`，**P2-A 的 profile 仍必须共享**

### 1.2 明确不做

- 语音打断、回声消除到能双讲
- Live2D 口型（P4 用本阶段的音频）
- QQ 语音消息
- 本仓库内训练 / 拷贝 GPT-SoVITS 权重

## 2. 架构

```
麦克风 -> ASR（中文）-> Gateway/Agent（LLM 出日语）
                         ├-> 日→中 翻译 -> 中文气泡
                         └-> speech/tts.py（speech_ja）-> wav
前端谁先好谁先上：文字不必等音频
（P4）同一音频给 Live2D 口型
```

文字输入路径保持不变。语音只是另一种 Inbound。

---

## 3. 选型（P3 锁定一个组合）

| 组件 | 首选 | 备选 | 说明 |
| --- | --- | --- | --- |
| ASR | Faster-Whisper `small`/`medium` 或 SenseVoice | 云端 ASR | 中文准、可离线优先 |
| TTS | **GPT-SoVITS** 本机 API | 引擎挂了则静音+中文 | 只合成日语。输入必须是 `speech_ja`。权重在原训练项目，本仓库只 HTTP |
| 传输 | WS 发 `user_audio` 元数据 + 二进制；或 `POST /api/speech/recognize` | | 实现简单优先 |

`speech/asr.py`、`speech/tts.py` 对外只要：

```text
async def transcribe(audio_bytes, mime: str) -> str
async def synthesize(text: str) -> bytes   # wav
```

## 4. 协议补充

客户端 → 服务端：

```json
{ "type": "user_audio_start" }
```

随后二进制帧，或一条：

```json
{ "type": "user_audio", "mime": "audio/webm", "data_base64": "..." }
```

服务端 → 客户端（在原有 `assistant_text` 之外）：

```json
{ "type": "user_transcript", "text": "识别出的话" }
{ "type": "assistant_audio", "mime": "audio/wav", "url": "/media/tts/xxx.wav" }
```

音频文件写 `data/tts_cache/`，按 hash 或 uuid 命名，gitignore。提供 `GET /media/tts/{id}` 仅本机。

**播放策略：** 译文和音频并行。气泡不必等 wav；wav 不必等译文。不要等两样都齐才动。

---

## 5. 对话状态机（P3 简化）

```
idle → recording → transcribing → thinking → speaking → idle
```

- `speaking` 期间禁用新录音（P5 才允许打断）
- 转写为空 / 过短：不调 LLM，提示没听清
- TTS 失败：仍显示文字，前端提示「语音合成失败」

## 6. 配置

```yaml
speech:
  asr:
    engine: faster_whisper   # 或 sensevoice / cloud
    model: small
    language: zh
  tts:
    engine: gpt_sovits       # 锁定
    api_base: http://127.0.0.1:9880
    # 参考音频与 prompt 只写本机路径，禁止提交
    ref_wav: ""
    prompt_text: ""
  max_recording_s: 30
```

**GitHub 能推的：** 本仓库源码、人设、调用 GPT-SoVITS 的客户端（`speech/tts.py` 打 HTTP）。

**不能推、也不要拷进本仓库的：**

- GPT-SoVITS 整棵工程（本机放在 `E:\work space\ai\vits\GPT-SoVITS`）
- 预训练底模、自炼或第三方 `.pth` / `.ckpt`
- `data/natsume/` 里的干声、标注、权重、参考 wav、试听
- gal 干声、UVR 中间件、Live2D 拆包

P3 **不炼丹**。权重已在别的项目练好并给本机 GPT-SoVITS 加载。本仓库 `synthesize(speech_ja)` 只请求 `127.0.0.1:9880`。推理参考句见 [本地资源.md](../本地资源.md)，路径写进本机 config，不进 git。

## 7. 实现顺序

1. 封装 `transcribe` / `synthesize`，用本地 wav 单测
2. HTTP 上传识别打通
3. 聊天页录音按钮
4. Agent 回复后自动 TTS
5. 状态机：录音互斥、失败提示
6. 验收：同一 **P2-A** 记忆在纯文字与语音之间共享（含重启）

---

## 8. 验收

- [ ] 浏览器授权麦克风后能录音
- [ ] 说一句中文，气泡出现接近原意的转写
- [ ] 她的中文气泡随后出现，并自动播放日语语音（二者并行，不必互相等待）
- [ ] 音色稳定，连续 5 句是同一个人声
- [ ] 语音聊到的事实，刷新后纯文字再问仍在（P2-A 记忆，重启后端也在）
- [ ] 空白录音 / 噪音：提示没听清，不产生胡乱记忆候选
- [ ] 播放期间不能再开第二路录音（P3）
- [ ] 端到端延迟有记录（日志一行即可），目标 < 4s 不作为硬失败，但要可测量

---

## 9. 交给 P4 的接口

P4 需要的不是新 Agent，而是：

- 每次 TTS 产出的 **wav 可被前端拿到**（url 或 PCM）
- 每次 Outbound 继续带 **emotion**
- 播放时钟：前端能对音频做 RMS 或把 viseme 时间轴对齐

P3 结束时在 `assistant_audio` 里保留 `url` + `duration_ms` 字段，P4 直接用。

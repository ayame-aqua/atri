## 1. 本阶段要做成什么样

在企业微信或公众号里能文字来回，人设和记忆与网页、QQ 一致。只做一种通道，不要两种同时开工。

### 1.1 要做

- 拍板：**企业微信应用** 或 **公众号（含服务号客服消息）** 二选一
- `channels/wechat.py` 实现 `Channel`
- 验证签名、收文本、回文本
- 同一 `MemoryStore`；`chatId` 如 `wechat:dm:<openid>`
- 白名单（你的 userid / openid）
- 明文配置与回调 URL 说明（本机需内网穿透时，只为自用）

### 1.2 明确不做

- 把个人微信协议号当默认方案
- 公众号里做复杂菜单商城
- 语音/图片全模态（先文字；图片占位即可）
- 改人设或另训练一个「微信人格」

---

## 2. 怎么选

| 方案 | 适合 | 限制 |
| --- | --- | --- |
| 企业微信自建应用 | 你愿意开一个企业/团队微信，私聊更像工作聊天 | 对方也要在企微里 |
| 公众号 | 你已有或能注册公众号，用户给公众号发消息 | 体验是「公众号对话框」，不是好友气泡；有回复时限 |

P6 建议：**若只自己用、且能接受企微，优先企业微信应用**，接口更像长期私聊。若你已经有公众号，用公众号也行。

选定后写进 `config.yaml` 的 `channels.wechat.mode: wecom | official_account`。

官方文档按当时控制台为准，实现时对照最新接口，不要把过期 URL 写死在业务逻辑里。

---

## 3. 架构

与 QQ 相同：

```
微信回调/长连接 -> WechatChannel -> Gateway -> Agent -> wechat.send
```

禁止在微信适配器里直接调 LLM。

---

## 4. 配置草稿

```yaml
channels:
  wechat:
    enabled: false
    mode: wecom
    allow_users: []
    allow_all_when_empty: false
    token: ${WECHAT_TOKEN}
    encoding_aes_key: ${WECHAT_AES_KEY}
    corp_id: ${WECOM_CORP_ID}
    agent_id: ${WECOM_AGENT_ID}
    secret: ${WECOM_SECRET}
```

回调接口仅用于微信服务器验证与收消息。管理页仍只绑本机。

---

## 5. 行为

- 文本进 Agent，回复纯文本
- 超长切段（企微 / 公众号各自上限以官方为准，Channel 内切开）
- emotion 不发送
- 与 QQ 一样 fail-closed 白名单
- 不在本阶段做群机器人（企微群可列为可选，默认关闭）

---

## 6. 实现顺序

1. 选定 mode，跑通「收到 ping 回 pong」（可硬编码，不经 Agent）
2. 接 Gateway + 记忆
3. 白名单、切段、错误回复
4. 验收与网页/QQ 记忆一致性

---

## 7. 验收

- [ ] 只启用了一种微信官方通道
- [ ] 白名单用户文字来回，人设正确
- [ ] 在网页或 QQ 记住的称呼，微信侧仍知道
- [ ] 非白名单不回复
- [ ] 凭证在 `.env`，不进 git
- [ ] 个人微信协议登录不是默认路径（代码里即使有实验开关，默认 false 且文档标明不推荐）

---

## 8. 交给 P7

P7 不依赖微信特有逻辑。微信通道保持「文字 Channel」即可。桌宠与打断只作用于本机语音/窗口。

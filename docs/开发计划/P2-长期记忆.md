## 1. 本阶段要做成什么样

新开一个浏览器会话、甚至重启后端，她仍然知道你的称呼和关系。你能在本机页面上看见、改掉、忘掉某条记忆。

先做「记得住」，不做「自动变成完美日记」，也不接 QQ。

### 1.1 要做

- SQLite 核心事实表（每次对话全量注入）
- 情节记忆（会话摘要 + 向量检索 Top-K）
- 风格 / 黑话表结构（P5 才自动灌；本阶段可手动导入）
- 记忆候选：模型提出 → 低风险自动写 / 高风险待确认
- 本机「记忆」管理页：列表、确认、编辑、删除
- 「记住：」「忘掉：」自然语言指令
- 离线脚本：吃一份**你自己的群导出文本**，产出待确认条目

### 1.2 明确不做

- QQ / 微信在线拉群
- 微调 / LoRA
- 把群里别人的电话、地址写进对你的 profile
- 无限写入、不经确认的「她觉得的」记忆

## 2. 记忆三层

| 层 | 表 / 集合 | 注入方式 | 谁能写 |
| --- | --- | --- | --- |
| profile | `facts` 中 `scope=profile` | 每次对话全量 | 你确认；或明确指令 |
| episodes | `episodes` + 向量 | 按当前用户句检索 3–8 条 | 会话结束摘要；可待确认 |
| style | `style_terms` | 最多 N 条（默认 8）已确认项 | 导入 / 日后 P5；必须人工确认 |

Prompt 里必须标明来源，避免模型把记忆当成「刚刚发生的对话」。

---

## 3. 数据模型

文件：`data/memory.sqlite`（不入库）  
向量：`data/vectors/`（Chroma 或 LanceDB，二选一写进 config）

### 3.1 `facts`

| 列 | 说明 |
| --- | --- |
| id | PK |
| key | 如 `user.display_name`、`user.nickname_from_her`、`relationship`、`timezone`、`rule.*`、`prefers.*`、`dislikes.*` |
| value | 文本 |
| category | `identity` / `relationship` / `rule` / `preference` / `other` |
| status | `active` / `pending` / `archived` |
| source | `user_cmd` / `extract` / `manual` / `group_import` |
| evidence | 原话摘录，可空 |
| created_at / updated_at | |

**P2 启动时预置空行或占位，但必须支持这些 key：**

- `user.display_name`
- `user.nickname_from_her`
- `relationship`
- `created_together_at`
- `rules`（可用多行 `rule.<slug>`）

### 3.2 `episodes`

| 列 | 说明 |
| --- | --- |
| id | PK |
| summary | 一两句 |
| happened_at | |
| source_chat_id | 如 `web:local` |
| status | `active` / `pending` |
| embedding_id | 指向向量库 |

### 3.3 `style_terms`

| 列 | 说明 |
| --- | --- |
| id | PK |
| term | 词或梗 |
| meaning | 含义 |
| usage | 她该怎么用 |
| status | `candidate` / `confirmed` / `rejected` |
| evidence | |
| count | 出现次数 |

### 3.4 `memory_candidates`（可选独立表）

未确认抽取结果队列，管理页消费。

## 4. 写入规则

| 触发 | 行为 |
| --- | --- |
| 用户说「记住：我讨厌被催」 | 直接写 `dislikes.rushed`，`status=active`，`source=user_cmd` |
| 用户说「我叫李雷，你叫我雷雷」 | 写 display_name 与 nickname；关系若未设，可生成 pending |
| 用户说「忘掉 xxx」 | 模糊匹配 key/value，归档或删除，回复确认 |
| 模型抽取到「他明天要出差」 | 进 pending episode，不自动当 profile |
| 关系、忌讳、重要承诺 | 一律 pending，管理页勾选后才 active |
| 群导入 | 全部 pending / candidate |

**禁止自动覆盖**已有 `relationship`、`rule.*`，除非用户明确说改。

每轮 LLM 除聊天外可输出 JSON 块（对用户隐藏）：

```json
{
  "emotion": "happy",
  "silent": false,
  "memory_candidates": [
    { "layer": "profile", "key": "prefers.tea", "value": "喝茶不喝咖啡", "confidence": 0.8 }
  ]
}
```

P1 的 `[[emotion:]]` 可升级为统一 JSON 尾块；要兼容旧格式。

## 5. 检索与拼装

Agent system 顺序（相对 P1 插入第 2–4 步）：

1. 人设
2. **全部 active profile 事实**（格式：`- key: value`）
3. **最多 8 条 confirmed style**
4. **检索到的 episodes**（标注「长期记忆，不是当前对话」）
5. 通道规则
6. 最近 N 轮
7. 当前句

`retrieve(query)`：用当前用户文本（及最近两轮）查向量，过滤 `status=active`。

会话结束（页面关闭或空闲超过阈值，P2 可用「手动点生成摘要」降低复杂度）：对最近对话做一次摘要，写入 pending 或低风险 active episode。P2 最低实现：**一次会话结束 API** `POST /api/memory/summarize-session`。

## 6. 接口

全部仅 `127.0.0.1`。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/memory` | 管理页 |
| GET | `/api/memory/facts` | 列表，可按 status 过滤 |
| POST | `/api/memory/facts` | 手建 |
| PATCH | `/api/memory/facts/{id}` | 改 value / 确认 pending |
| DELETE | `/api/memory/facts/{id}` | 删除 |
| GET | `/api/memory/episodes` | |
| GET | `/api/memory/style` | |
| POST | `/api/memory/style/{id}/confirm` | 黑话转正 |
| POST | `/api/memory/summarize-session` | 摘要当前 Web 会话 |
| POST | `/api/memory/forget` | body: `{ "query": "忘掉催我" }` |

聊天路径仍是 `/ws/chat`。Agent 每轮读 MemoryStore，不经前端塞记忆。

## 7. 离线群导入（预演，不是 QQ 通道）

`scripts/ingest_group_export.py`

- 输入：你从**自己的群**导出的 txt/json（路径通过参数传入，文件放 `data/imports/`，gitignore）
- 清洗：去系统提示、入群消息、明显广告
- 抽候选：调 LLM 输出 facts / style_terms / episodes，**全部 pending**
- 不把其他人隐私（手机号、住址、证件）写入；正则丢掉数字串过长的内容
- 不自动 confirmed
- **不发起任何网络到 QQ**

本阶段用一份脱敏样例跑通即可，不要求真群。

## 8. 实现顺序

1. `schema.sql` + SQLite `MemoryStore`
2. Agent 注入 profile_block（先手写两条事实验证）
3. 「记住 / 忘掉」指令解析
4. 候选 JSON + pending
5. `/memory` 管理页
6. episodes + 向量检索
7. style 表 + 导入脚本
8. 按第 9 节验收

## 9. 验收

- [ ] 说「我叫 X，你叫我 Y」，重启后端再开页面，她仍正确称呼
- [ ] `relationship` 可在管理页改、删，下一轮对话立刻生效
- [ ] 「记住：我讨厌被催」写入 facts 且可在管理页看见
- [ ] 「忘掉被催」后她不再主动用这条
- [ ] pending 条目未确认前不进 prompt
- [ ] 进程重启 sqlite 文件还在
- [ ] 导入脚本对样例文件只产生 pending/candidate，不发 QQ
- [ ] 仍无 QQ/微信登录代码

## 10. 交给 P3 的接口

语音通道必须复用同一个 `MemoryStore` 与同一个 `chat` Agent。  
P3 新增 `chatId`（如 `voice:local`）时，**profile 全局共享**；episodes 可带 `source_chat_id`，检索默认跨通道（自用，你就是你）。

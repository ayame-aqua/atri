# 双模式：桌宠陪伴 vs QQ 社交

| 项 | 内容 |
| --- | --- |
| 性质 | 跨阶段产品原则，不是单独开发步 |
| 首次版本 | v0.3 |
| 最近修订 | v0.11 |
| 变更记录 | [变更/](../变更/) |
| 写入原因 | 本地和 QQ **不是同一套说话策略**，必须一开始就分清 |
| 相关阶段 | 本地：P1→P2-A→P3→P4 打底，P5 做成桌宠；QQ：P6 就必须自主发言 + 表情包 |

---

## 1. 一句话

**在你电脑上，她是会吵你、会看屏幕、会连续聊天的伴侣。**  
**在 QQ 里，她是会潜水、会自己决定张不张嘴、会发表情包的群友。**

同一套人设和记忆，两套社交策略。禁止把「条条必回」用在 QQ，也禁止把「默认潜水」用在桌宠。

---

## 2. 对照

| | 桌宠 / 本机（web → 桌面窗） | QQ（私聊你 / 你自己的群） |
| --- | --- | --- |
| 关系 | 一直在你旁边 | 群友 / 好友，有自己的社交分寸 |
| 回不回 | **默认要聊**。你一说话就接；冷场了也常主动找你 | **默认先看再决定**。可以 silent；@、点名、好玩、有梗才出声 |
| 主动 | **经常**搭话：闲太久、你换了窗口、到点了、想起约定 | 群冷场偶尔试探；不能刷屏；私聊也比桌宠克制 |
| 感知 | **CV**：周期性看屏幕（可选摄像头），知道你在干什么 | 能看群消息、图、表情包；不看你的桌面 |
| 输出 | 语音 + Live2D 口型表情；本机不必发表情包 | 短句 + **表情包**（已有 / 收集 / MCP 生成） |
| 工具 | 看屏、主动开话题、打断 | 读未读、发消息、发/收/生成表情包 |
| 失败姿态 | 没听清就问 | 不确定就潜水，不要乱回 |

策略模块建议拆开，不要一个 `if` 打天下：

- `src/core/policy/local.py` — 陪伴策略  
- `src/core/policy/qq.py` — 社交策略  

Gateway 按 `inbound.channel` 选策略，再进 Agent。

## 3. 桌宠模式（P5 做满，P1 先当「必回私聊」）

### 3.1 连续聊天

- 同一条会话一直开着，不是客服工单
- P3 起语音；P5 起可打断、可边听边说
- 允许她连续说几句（分条 TTS），你插话则停

### 3.2 主动搭话（要勤，但可调）

触发源（可组合）：

1. 你超过 N 分钟没理她（默认偏短，例如 5–15 分钟，config 可调）
2. 屏幕内容明显变化（切到游戏、视频、IDE、聊天软件）
3. 到了记忆里的点（该吃饭、说好要早睡）
4. 随机碎碎念（低概率，避免机械闹钟感）

主动消息也是 `InboundMessage`，`chatType=system`，例如：`[屏幕] 用户正在全屏播放视频，标题像是……`。走同一 Agent，这样记忆和人设生效。

必须有：**静音 / 勿扰**（快捷键或桌宠菜单）。勿扰时 CV 可停、主动搭话停。

### 3.3 CV：看见你在电脑上做什么

本机功能，**不经过 QQ**。

| 能力 | 做法 | 阶段 |
| --- | --- | --- |
| 屏幕理解 | 定时或窗口切换时截屏 → 多模态 LLM 或「先描述再聊天」 | P5 |
| 窗口标题 | 先读前台进程/标题，截屏作补充（更省、更稳） | P5 可先做标题，再上截屏 |
| 摄像头 | 可选，默认关 | P5 以后，不阻塞 |

隐私（写进配置，默认保守）：

- 仅本机处理；截屏默认不落盘，或只留最近一张调试图且 gitignore
- 窗口黑名单：密码管理器、银行、支付、指定进程
- 热键暂停「看屏幕」
- 人设里写明：看见了可以调侃或关心，不要把屏幕上的秘密写进长期记忆，除非你明确说「记住」

P1–P4 **不实现**截屏。P1 的 `InboundMessage` 预留 `vision` 字段即可。

## 4. QQ 模式（P6 就必须是这样，不是桌宠做完才开始装潜水）

### 4.1 自行决定是否发言

不要「每条群消息自动生成回复再发出」。正确循环类似：

```text
群事件进来（可以先入未读队列）
    → 策略允许 Agent 醒来（或 Agent 自己用工具拉未读）
    → Agent 输出 silent / 文本 / 表情包 / 多条
    → 只有非 silent 才 send
```

**私聊你：** 比群积极，但仍允许她回表情、回很短、或偶尔「嗯」——不要桌宠那种不停找话题。  
**群：** 学习与发言分开；没趣就 silent。

P6 最低：Agent 必须能输出 `silent: true` 且通道真的不发。观望/活跃/唤醒状态机在 **P6 做完第一版**。

### 4.2 表情包三件事（P6 范围）

1. **发送已有表情包**  
   本地表情库 `data/stickers/`：文件 + 索引（id、标签、来源、备注）。Agent 用工具按语义选一个发。

2. **收集群友表情包**  
   群里有人发表情，她可以收入库（来源群、发送者昵称、时间、文件 hash 去重）。管理页可删。只收你允许的群。

3. **MCP 生成表情包再发**  
   Agent 调工具：`sticker_generate(prompt, text?)` → 出图（png/gif）→ 入库 → 作为图片/自定义表情发出。  
   生成要限频（例如每小时 N 张），失败就改发文字或已有表情，不许卡死。

官方机器人往往只能发**图片**当表情用；专用号网关更接近真·表情包。P6 选接入方式时把这条写进决策：要「像群友发表情」优先考虑能力更完整的通道，对 Core 仍只暴露 `send_sticker(sticker_id | image_path)`。

### 4.3 MCP 工具（给 QQ Agent 用，白名单）

建议独立 MCP server `src/mcp/qq_social.py`（或同等内部 tool 表，协议用 MCP 是为了和后续工具生态一致）：

| 工具 | 作用 |
| --- | --- |
| `qq_get_unread` | 看未读，自己决定回不回 |
| `qq_send_text` | 发纯文本，强制白名单 |
| `qq_send_sticker` | 按 id 或路径发表情 |
| `qq_list_stickers` | 列本地库（含标签、来源） |
| `qq_collect_sticker` | 把当前/指定消息的表情收入库 |
| `sticker_generate` | 文生图生成表情并入库 |
| `qq_sticker_note` | 给已有表情写备注（「嘲讽用」「晚安」） |

生成图用你自己的 API Key 或本地生图，封装在 tool 里，模型看不见密钥。

## 5. 和开发顺序怎么对齐

执行顺序：**P1 → P2-A → P3 → P4 → P5 → P6 → P7**（编号已对齐）。硬依赖表见总纲 §3.1。

| 阶段 | 双模式落到哪 |
| --- | --- |
| P1 | 本地 = 必回陪聊；Outbound 预留 `silent`（Web 恒 false）；`[[atri]]` 尾块；不接 QQ |
| P2-A | 记忆共享（事实表）；屏幕内容默认不进 profile |
| P2-B | 情节 / 风格补强，不挡语音和桌宠 |
| P3–P4 | 本地语音和脸，仍是「你说她回」；已与文字共用记忆 |
| P5 | 桌宠连续聊、频繁主动、CV 看屏、打断；**本阶段不接 QQ** |
| P6 | QQ 自主发言 + 表情包收/发/生成；状态机一次性做完 |
| P7 | 个人微信先过合规门再接文字；不走企微 / 公众号；过不了则实验性可卸载 |

## 6. 验收时用来打脸的反例

做错：

- 桌宠：你两小时没说话，她一直安静当壁纸
- 桌宠：她完全不知道你在打游戏 / 写代码
- QQ：群里每句话都回，像客服
- QQ：只会打字，不会发表情包
- QQ：表情包不能从群友那收，也不能自己生成

做对：

- 桌宠会冷不丁说「写这么久了，眼睛酸不酸」
- 你让她别吵，她真的停
- 群里她大部分时候潜水，偶尔丢一张很准的表情包
- 新梗表情被她收进库，下次还能用

## 1. 项目是什么

做一个只给自己用的 **四季夏目（Shiki Natsume）**：先在本机做成能对话、有长期记忆、能听能说、皮会动、**知道你电脑上在做什么** 的桌宠（对齐 [Project AIRI](https://github.com/moeru-ai/airi) 那类能力，模型跑我们自己的）。QQ / 微信放在**最后**，对齐桌宠之后再出门。

不直播。她不是客服。本地和 QQ **不是同一种说话方式**，见 [双模式说明.md](./双模式说明.md)：

- **桌宠 / 本机：** 连续聊天，经常主动找你，能看见你在电脑上做什么（CV）。
- **QQ：** 自己决定说不说；能发表情包、收集群友表情包、用 MCP 生成表情包再发。

**工作名：** 四季夏目（Shiki Natsume。人设 `characters/natsume.md`。GitHub 仓库：`ayame-aqua/shiki-natsume`）

## 2. 目标与非目标

### 2.1 要做

- 网页能聊，同一套大脑接到桌宠
- 固定人设，不漂移成通用助手
- 长期记忆：称呼、关系、约定（P2-A 硬门；P2-B 向量补强不挡出声）
- 多模态本机：语音听和说（P3）、Live2D（P4）、看屏幕（P5）
- 桌宠：Neuro-sama / AIRI Tamagotchi 那种展示；主动搭话 + 知道你在干什么
- QQ / 微信：**P5 对齐之后才做**，放在主线最后

### 2.2 不做（总原则）

- 直播、弹幕、公域运营
- 采集或训练你没有管理权、未经说明的群
- 一开始就微调大模型
- 把桌宠的「不停找你聊」同步到 QQ 群
- 把 QQ 的「默认潜水」用在桌宠
- P1 就做桌宠 / 看屏 / QQ 登录
- 把核心设计绑死在尚未确认合规的个人微信适配器上

## 3. 开发顺序（已确认）

**编号 = 执行顺序。** 主线先对齐 AIRI 级本机陪伴，**P6 / P7 放在最后出门**。

执行顺序：**P1 → P2-A → P3-A → P4 → P5 →（本机对齐）→ P6 → P7**。P3-B / P3-C 听你、实时轮次不挡口型。P8 换自有底模，不插进对齐、也不挡桌宠；有语料再做。

### 3.0 本机对齐（对标 AIRI，不是 Fork）

P5 验收前，目标就是 AIRI Tamagotchi 那类事，用我们的人设和模型：

| AIRI 有的 | 我们对应 | 阶段 |
| --- | --- | --- |
| 能聊天 | 网页 + 同一 Agent | P1 |
| 长期记忆 | SQLite 事实；向量是 P2-B | P2 |
| 语音 | 先 SoVITS 出声（P3-A），再 ASR 听你（P3-B），再实时轮次（P3-C） | P3 |

| 桌宠窗 + 看屏 | 透明置顶；前台窗口 + 截屏进 Agent | P5 |

**抄接法，不抄成又一个 AIRI / FaustBot / Artemis。** 对照表见 [借鉴.md](./借鉴.md)。仓库 MIT 的桌宠截屏、Live2D 驱动、SoVITS HTTP provider 可以借鉴并保留版权声明。Cubism SDK、官方皮、SoVITS 权重不是 AIRI 能授权的。Minecraft / 多角色市场 / 后宫热切换 / FaustBot Agile 不搬。LLM 默认仍是我们的 OpenAI 兼容端点，P8 才换自有权重。

P5 没验收，禁止 QQ / 微信登录代码。

P2 拆成两截，避免「完整记忆中枢」挡住听见她说话，也避免「先语音后记忆」导致重启失忆：

| 切分 | 内容 | 是否挡住下一硬阶段 |
| --- | --- | --- |
| **P2-A 最小记忆** | 称呼、关系、明确「记住」的事实、SQLite 落盘、「忘掉」、简单查看/编辑页 | **本机已验收**（2026-09-17）。P2-B 仍不挡语音 |
| **P2-B 记忆补强** | episodes、向量检索、风格/黑话库、群导出导入、完整待确认队列 | **否**：不挡 P3/P4/P5；**本机已验收**（2026-09-18） |
| **P2-C 记忆再补强** | mem0 接法（自研 add/search）+ 日记/门槛/核心印象 + 轻量相处状态（精力/别扭/亲近） | **否**：不挡 P4；**已关闭**（2026-09-19） |

## 4. 总体架构

所有入口（网页、语音、QQ、以后的微信）只产生同一种内部消息。大脑、记忆、人设只有一份。

```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│  Web 聊天    │  │  麦克风/喇叭 │  │  QQ 通道    │  │ 微信通道    │
│  (P1)       │  │  (P3)       │  │  (P6)       │  │  (P7)       │
└──────┬──────┘  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘
       └───────────────┴────────┬────────┴────────────────┘
                                ▼
                    ┌───────────────────────┐
                    │  Channel Gateway      │
                    │  统一内部消息 Inbound  │
                    └───────────┬─────────┘
                                ▼
                    ┌───────────────────────┐
                    │  Agent Core           │
                    │  人设 + LLM + 工具     │
                    │  local 策略 ≠ qq 策略  │
                    └───────────┬─────────┘
                          ┌─────┴─────┐
                          ▼           ▼
                 ┌────────────┐ ┌────────────┐
                 │ Memory     │ │ MCP/工具    │
                 │ 事实/口吻   │ │ 表情/看屏   │
                 └────────────┘ └────────────┘
                          │
            ┌─────────────┼─────────────┐
            ▼             ▼             ▼
      ┌──────────┐  ┌──────────┐  ┌──────────┐
      │ TTS 音频  │  │ Live2D   │  │ 各通道回复 │
      └──────────┘  └──────────┘  └──────────┘
```

微信通道在架构图里是可插拔的：Core 不得 `import` 微信实现细节；P7 若降为实验性适配器，关掉配置后系统其余部分照常。

### 4.1 内部消息（P1 起定字段，后续只填值、可加可选字段）

协议允许 **加可选字段**，不允许默默改语义。P2-B / P5 / P6 只往可选位置填。

```text
InboundMessage {
  messageId: string           // 客户端或通道生成的 UUID；同一 id 在去重窗口内只处理一次
  channel: "web" | "voice" | "qq" | "wechat"
  chatType: "dm" | "group" | "system"
  chatId: string              // 会话键，例如 web:local / qq:private:xxx / qq:group:xxx
  senderId: string
  senderName: string
  text: string
  replyTo?: { senderName, text }
  mentionedSelf: boolean
  createdAt: number
  rawType?: "text" | "image" | "voice" | "sticker" | "other"
}

OutboundMessage {
  messageId: string           // 本轮回复 id
  replyToId: string           // 对应的 inbound.messageId
  chatId: string
  texts: string[]             // 可分多条；可为空（只发表情）
  emotion?: string            // happy / sad / angry / shy / neutral
  audioUrl?: string
  speechJa?: string           // 日语台词；P3 送给 SoVITS
  visemes?: any               // P4 口型
  silent?: boolean            // QQ 允许不回；桌宠 / Web 默认 false
  stickerIds?: string[]       // P6 表情包
}

InboundMessage.vision?        // P5：屏幕描述 / 截屏引用，P1 只预留字段
attachments?:                 // P6：sticker / image / voice
```

**重复消息：** 通道必须带 `messageId`。Gateway 对 `(chatId, messageId)` 在可配置窗口（默认 10 分钟）内去重：已成功处理则不再调 LLM，返回缓存的 Outbound 或 `error.code = DUPLICATE`（见 P1 WebSocket）。重试未完成的请求可以接着跑，但不得并发跑两次同一 id。

### 4.2 LLM 输出协议（P1 起唯一格式）

模型对用户可见的正文之后，必须跟不可见结构化尾块。人设文件、Agent 解析器、P2 记忆抽取共用这一份，禁止再维护 `[[emotion:]]` 与 JSON 两套。

```text
<可见回复，可多段，不要念出下面的块>

[[natsume]]
{"emotion":"happy","silent":false,"memory_candidates":[]}
```

- 标记行必须恰好是 `[[natsume]]`。
- 其后是 **一个** JSON 对象，可单行；不要包代码围栏。
- `emotion`：`neutral` | `happy` | `sad` | `angry` | `shy`
- `silent`：本地通道恒按 false 执行；P6 才允许 true 且通道真的不发
- `memory_candidates`：P2-A 起消费；P1 解析后丢弃或忽略即可，但格式必须能 parse。**value 用中文**（记忆给用户看、给 prompt 用）

**语言（已拍板）：** 标记之前的可见正文是 **中文台词**（气泡直接用）。用户聊中文，输入不转日语。日语由系统另译，写入 `speech_ja` 给 P3 TTS。详见 §4.3。

**解析失败降级（必须写测试）：**

| 情况 | 可见文本 | emotion | silent | memory_candidates | 日志 |
| --- | --- | --- | --- | --- | --- |
| 没有 `[[natsume]]` | 全文（再剥一层遗留 `[[emotion:x]]` 若存在） | 有遗留行则用其值，否则 `neutral` | `false` | `[]` | warning |
| 有标记但 JSON 非法 | 标记之前的文本 | `neutral` | `false` | 不写入任何记忆 | error |
| JSON 合法但缺字段 | 标记之前 | 缺则 `neutral` | 缺则 `false` | 缺则 `[]` | warning |
| `emotion` 不在枚举 | 标记之前 | `neutral` | 按 JSON | 按 JSON | warning |
| 未知 JSON 键 | 忽略未知键 | 已知字段照常 | | | debug |

永远不要把 `[[natsume]]` 及其 JSON、或遗留的 `[[emotion:]]` 推给用户。遗留 `[[emotion:x]]` 只作为无新标记时的兼容，模型侧禁止再教这套。

### 4.3 中文气泡 + 日语 TTS（并行）

用户用中文说，气泡用模型直接写的中文。日语只服务语音，由短翻译请求从中文译出，避免「先写日语再译中文」把你正在看的字译成电报。

```text
LLM 整段吐出中文正文
        ├──────────────┬──────────────┐
        ▼              ▼              ▼
   解析 [[natsume]]   中→日 翻译     （P3）GPT-SoVITS 吃 speech_ja
        │              │              │
        └────── 气泡不必等日语；音频不必等你读完字 ──────┘
```

- **P1（无 TTS）：** 中文出齐 → 推前端；同时把中文译成日语写入 `speech_ja`（失败则留空，不影响气泡）。
- **P3：** 中文出齐后推气泡，日语译文送 SoVITS。整轮目标仍 2–4s。
- **P5：** 流式按句切开再并行合成。
- 翻译失败：气泡仍是中文；不播或静音，禁止再开一轮带人设的 LLM。
- 会话历史：用户句中文；她的句也存中文。注入 prompt 只用中文，避免中日混飞。
- 用户输入**不**翻译成日语。

SoVITS **权重已在别的项目炼好**。本仓库不训练、不拷 ckpt；只请求本机已启动的 API（默认 `127.0.0.1:9880`）。

## 5. 技术选型（P1–P4 锁定，P5 桌宠，P6 再扩 IM）

原则：本地可跑、接口可换、先云端 LLM 也行。

| 层 | P1–P2 选型 | 备注 |
| --- | --- | --- |
| 语言 | Python 3.11+（后端）+ 简单 Web 前端 | 语音/Live2D 生态更熟 |
| 工程基线 | `pyproject.toml` + 锁文件（`uv.lock` 或等效）+ pytest | P1 就必须有；CI 跑测试，不只 ruff |
| 后端 | FastAPI + WebSocket | 网页聊天与后续语音同一条 WS |
| 前端 P1 | 单页 HTML/Vue 或纯静态 + WS | 先能聊，不做复杂 UI 框架绑架 |
| LLM | **默认云端** OpenAI 兼容接口（DeepSeek / 通义等） | 本机 Ollama 仅断网后备，不和 SoVITS 抢 GPU |
| 人设 | `characters/natsume.md` + `system` 拼装 | 四季夏目；与 LLM 分离 |
| 记忆 | P2-A：SQLite 事实表；P2-B：再加向量库（Chroma 或 LanceDB） | 默认称呼「你」 |
| 配置 | `config.yaml` + `.env` | 密钥不入库 |
| 语音 ASR | P3：SenseVoice 或 Faster-Whisper | 中文优先 |
| 语音 TTS | P3：本机 GPT-SoVITS 推理（日语） | 权重已在别的项目炼好；本仓库只打 HTTP。见 §4.3 |
| Live2D | P4：natsume 模型（Cubism 3–5） | 口型 + emotionMap；未授权资源不进 git |
| QQ | P6 再定适配器 | 自主发言 + 表情包；对 Core 暴露 text/sticker |
| 表情 MCP | P6：生成 / 入库 / 发送 | 密钥只在 tool 进程；P6 第一版可用内部 tool |
| 看屏 CV | P5：窗口标题 + 截屏 | 仅桌宠策略可用 |
| 微信 | P7：个人微信 Channel，可卸载 | 不走企业微信、公众号；先过合规门 |

不在 P1 引入：Electron 桌宠、VTube Studio 强绑定、微调训练框架、QQ SDK。

## 7. 模块设计

### 7.1 P1 人设与文字聊天

**人设文件：** `characters/natsume.md`（四季夏目）。最少包含名字、对对方的称呼、性格、禁区、`[[natsume]]` 输出约定。

- 默认用「你」，偶尔可用记忆里的昵称；不要叫「主人」。关系是女朋友，外冷内热、四爱向、安静陪伴
- 不承认自己只是 prompt，不改成别人
- 短句口语；模型正文出中文气泡；日语由系统另译给 TTS

**对话循环：**

1. Web 收到用户**中文**文本 → `InboundMessage`（含 `messageId`）
2. 取人设 + 短期上下文 + MemoryStore（P1 为空，P2-A 起有 profile）
3. LLM 生成 **中文**正文 + `[[natsume]]` 尾块
4. 中文推前端；另译日语写入 `speech_ja`；历史只注入中文

**短期上下文：** 当前会话最近 N 轮（建议 20）。与长期记忆分开。

工程基线见 P1 文档：`pyproject.toml`、锁文件、pytest、错误码、WS 去重。

### 7.2 P2 长期记忆

先做「记得住」，不做「自动变成完美日记」。

**P2-A（硬门）：**

- SQLite `facts`：`user.nickname_from_her`（默认「你」）、`relationship`、`created_together_at`、`rules`、任意 `key/value`
- 「记住：」「忘掉：」
- 简单本机查看/编辑/删除页
- 消费 `memory_candidates` 里低风险项；高风险可先只支持用户明确指令，完整 pending 队列可放到 P2-B

**P2-B（补强，不挡 P3）：**

| 类型 | 例子 | 写入 | 注入 |
| --- | --- | --- | --- |
| 情节记忆 episodes | 「上周说过要早睡」 | 会话结束后摘要 | 按相似度检索 Top-K |
| 风格/黑话 style | 群里的梗、她该用的口吻 | P6 群吸收；P2-B 可手动导入 | 少量、需确认后才进人设上下文 |
| 待确认队列 | 模型抽取的候选 | 管理页勾选 | 未确认不进 prompt |

**写入策略（避免乱记）：**

- LLM 每轮可在尾块提出 `memory_candidates`
- 自动写入仅限低风险字段（称呼、明确「记住：」指令）
- 关系、忌讳、重要承诺：进待确认（P2-B）；P2-A 可要求必须用户指令才写这些 key
- 用户说「忘掉 xxx」必须能删

**检索：** P2-A 核心事实全量注入；P2-B 再加情节记忆向量检索 3–8 条。上下文里明确标注「这是记忆，不是当前对话」。

### 7.3 P3 语音

**P3-A 出声（挡 P4）：**

- LLM 出中文；**同时** 中→日翻译送 SoVITS（§4.3）
- `speech/tts.py` 只打本机 GPT-SoVITS `api_v2`
- 中文气泡先上，wav 随后自动播；失败仍显示文字

**P3-B 听你（不挡 P4）：**

- ASR：中文语音 → 文本 → 走与 Web 相同的 Agent
- 乱音：不写胡乱记忆
- 与文字共用记忆

**P3-C 实时轮次（不挡 P4）：**

- 点「对话」持续听，停顿自动切句
- 她在说时不新开一句
- 不做抢话停播；流式切片和打断放 P5

### 7.4 P4 Live2D

- 模型：Cubism 3–5，放 `web/live2d/`
- 口型：音频 RMS 或 viseme 驱动 `ParamMouthOpenY`
- 表情：尾块里的 `emotion` → `emotionMap`（idle/happy/sad/angry/shy）
- P4 只做 Web 里的形象，不做透明桌宠（桌宠属 P5）

### 7.5 P5 桌宠陪伴

- 连续聊天 + **经常主动搭话**
- CV：窗口标题 + 截屏，让她看见你在电脑上做什么（可勿扰、窗口黑名单）
- 语音打断、更细情绪动作、透明桌宠窗
- 本阶段 **不接 QQ**；不要把看屏接到尚未存在的群通道

### 7.6 P6 QQ 通道

策略与桌宠相反，详见 [P6 方案](./P6-QQ通道/方案.md)。

- 群：未读批量 → Agent **自己决定** silent / 文字 / 表情包
- 禁止条条自动回复
- 表情包：发送本地库、收集群 U、MCP `sticker_generate` 后发送
- 学习与发言分开
- Channel 对外：`send_text` + `send_sticker`
- 自主发言状态机在 **P6 一次性做完**，不留到后面「再调参」

P6 之前若要预热记忆，只用自己群的**导出文本**跑导入脚本（P2-B）。

### 7.7 P7 微信

- 只走**个人微信**好友聊天
- 复用同一 Agent / Memory
- 不走企业微信，不做公众号
- **验收前必须完成合规可行性确认**（账号风险、平台许可、长期可维护性）。无稳定合规路径：适配器标为 experimental，默认关闭，Core 测试不得依赖它

### 7.8 P8 自有底模与 LoRA

- 现在只跑云端 API 的 demo，**P1–P7 不训练权重**
- P8 才换成可自部署的开源底模 + LLM LoRA（不是微调 DeepSeek 托管模型）
- 语料以原作里四季夏目自己的台词为主（本机、不入库）；网页陪聊里改过的 OOC 不当正例
- SoVITS 仍不在本仓库炼；P8 只换对话模型
- 详见 [P8 方案](./P8-自有底模与LoRA/方案.md)

## 8. 群数据：要「学习」，不是一上来微调

你的目标：她加**你自己的群**，用群里的数据变像你们这群人。

### 8.1 允许的数据

- 仅你作为群主/管理员的群
- 群成员应知道这是自用实验（即使只有你和号）
- 不采集陌生人群、不转发外群记录去训练

### 8.2 三层用法（按收益排序）

| 优先级 | 做法 | 阶段 | 说明 |
| --- | --- | --- | --- |
| 高 | 关系与事实抽取 | P6（可在 P2-B 用导出文件预演） | 谁是谁、怎么称呼、固定梗对应的意思 |
| 高 | 黑话/口吻表 | P6 / P2-B | 候选 → 你在管理页确认 → 注入 prompt |
| 中 | 情节摘要 | P2-B / P6 | 「某天群里发生过什么」进 episodes，检索用 |
| 低 | 微调 / LoRA | **P8** | 主料为原作夏目台词（本机）；陪聊 OOC 不当正例。P1–P7 禁止开工 |

**结论：P1–P7（当前 demo）不训练权重。** 主线里的「学习」是抽取 → 确认 → 写入 Memory/Style Bank。P8 才做 LLM LoRA，**主料是原作夏目台词**，不是把陪聊记录整锅端上去。

### 8.3 导入流水线（P2-B 可先做离线版）

```text
群导出文本 / P6 实时消息
    → 清洗（去系统消息、去广告、合并转发简化）
    → 抽取候选 {type, key, value, evidence, confidence}
    → 待确认队列
    → 你确认后写入 profile / style / episodes
    → Agent 上下文可引用
```

实时群消息额外规则：

- 默认学习，不默认发言
- 发言策略与学习策略分开配置
- 不把群里其他人的隐私事实当成对你的记忆（例如别人的手机号、地址）

## 9. Prompt 拼装（各阶段共用骨架）

顺序固定，避免记忆把人设冲掉：

1. 人设（`characters/natsume.md`）
2. 核心事实（你是谁、关系、约定）—— P2-A 起
3. 已确认黑话/口吻（少量）—— P2-B / P6
4. 检索到的情节记忆 —— P2-B
5. 通道规则（桌宠：主动陪聊；QQ：可沉默、可表情包）
6. 最近 N 轮对话
7. 当前用户消息

输出约定：只认第 4.2 节的 `[[natsume]]` 尾块。可见正文为中文台词；日语由 §4.3 翻译得到，给 TTS。

## 12. 风险

| 风险 | 应对 |
| --- | --- |
| 人设被模型冲成助手 | 人设里写死禁区；系统提示强约束；过长回复截断重试 |
| 尾块解析失败 / 两套协议 | P1 起只认 `[[natsume]]`；失败降级；单测锁行为 |
| 记忆记错 | 候选确认；核心事实手改；提供「忘掉」 |
| 语音延迟差 | P3 整段可验收；日语合成与中文翻译并行（§4.3）；流式切片与打断放 P5 |
| Live2D / 语音版权 | 只用有权使用的四季夏目资源；不把游戏拆包推进 git。SoVITS 权重留在原训练项目 |
| 本机 Python 过旧 | 已是 3.12；保持 ≥3.11 |

## 1. 项目是什么

做一个只给自己用的 AI 伴侣：能陪聊、有人设、有记忆、能语音、能驱动 Live2D 皮套。之后再接到 QQ，再接到个人微信。

不直播。她不是客服。本地和 QQ **不是同一种说话方式**，见 [双模式说明.md](./双模式说明.md)：

- **桌宠 / 本机：** 连续聊天，经常主动找你，能看见你在电脑上做什么（CV）。
- **QQ：** 自己决定说不说；能发表情包、收集群友表情包、用 MCP 生成表情包再发。

**工作名：** Digital Life（仓库：`digital-life`；角色名可另定）

## 2. 目标与非目标

### 2.1 要做

- 网页（及后续桌宠）文字 / 语音连续陪伴
- 固定人设，不漂移成通用助手
- 长期记忆：先记住你是谁、你们的关系、关键约定
- 语音：能听、能说；桌宠阶段可打断
- Live2D：口型跟随语音，表情跟随情绪
- 桌宠：主动搭话 + CV 看屏幕（P7）
- QQ：自主决定是否发言；表情包发送 / 收集群 U / MCP 生成（P5）
- 群数据：只从**你自己的群**吸收风格、黑话、关系（不微调）
- 个人微信（QQ 稳定之后；不走企业微信 / 公众号）

### 2.2 不做（总原则）

- 直播、弹幕、公域运营
- 采集或训练你没有管理权、未经说明的群
- 一开始就微调大模型
- 把桌宠的「不停找你聊」同步到 QQ 群
- 把 QQ 的「默认潜水」用在桌宠
- P1 就做桌宠 / 看屏 / QQ 登录

## 3. 开发顺序（已确认）

QQ **在计划内，但不是第一步。** 严格按下面 7 步推进，未完成当前步的验收，不开始下一步的功能开发。允许在当前步里**预留**下一步的接口。

| 阶段 | 内容 | 为什么是这个位置 | 本阶段验收 |
| --- | --- | --- | --- |
| P1 | 网页/桌面文字聊天 + 人设 | 先证明她「是谁」，其余都是皮肤 | 打开网页能聊；人设稳定；刷新后角色不丢 |
| P2 | 长期记忆 | 没有记忆就只是套了人设的 ChatGPT | 能记住你的称呼、关系、至少 5 条稳定事实，跨会话仍在 |
| P3 | 语音听和说 | 皮套的口型依赖音频，所以声音在前 | 能对着麦说话，她能回语音；延迟可先到 2–4 秒 |
| P4 | Live2D 口型与表情 | 有声之后再给身体 | 说话时嘴动；回复带情绪时切表情 |
| P5 | QQ 通道 | 文字/记忆/声音通了再挂即时通讯 | 自主决定说不说；能发表情包；能收集；能 MCP 生成 |
| P6 | 微信 | 好友聊天放 QQ 之后 | 个人微信私聊文字打通；无企微、无公众号 |
| P7 | 桌宠 + CV + 打断 | 本机陪伴要窗、要看屏、要主动 | 连续聊、常主动、能看你在干什么、能打断 |

### 3.1 阶段纪律

- P1 必须做出 **统一消息总线 + 通道接口**，即使第一个通道只是 Web。
- P2 必须做出 **记忆写入/检索 API**，后面 QQ 群数据走同一套，不另起炉灶。
- P5 才允许碰 QQ。账号形态（官方机器人或她的专用号）在进入 P5 时再拍板，适配器接口在 P1 就定好。
- P5 之前可以用你从群里**手动导出**的文本做记忆/风格语料预研，但不写 QQ 登录、收发、协议相关代码。

### 3.2 和「群数据训练」的关系

群不是第 0 步，也不是独立产品线。它挂在：

- **P2：** 定义「事实 / 风格 / 黑话」三种记忆类型，为群数据留字段。
- **P5：** 进你自己的群；学习 + **自主发言** + 表情包。
- **P7：** 只调 QQ 社交参数；桌宠才做主动和 CV。

详见第 8 节。

## 4. 总体架构

所有入口（网页、语音、QQ、以后的微信）只产生同一种内部消息。大脑、记忆、人设只有一份。

```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│  Web 聊天    │  │  麦克风/喇叭 │  │  QQ 通道    │  │ 微信通道    │
│  (P1)       │  │  (P3)       │  │  (P5)       │  │  (P6)       │
└──────┬──────┘  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘
       └───────────────┴────────┬────────┴────────────────┘
                                ▼
                    ┌───────────────────────┐
                    │  Channel Gateway      │
                    │  统一内部消息 Inbound  │
                    └───────────┬───────────┘
                                ▼
                    ┌───────────────────────┐
                    │  Agent Core           │
                    │  人设 + LLM + 工具     │
                    │  local 策略 ≠ qq 策略  │
                    └───────────┬───────────┘
                          ┌─────┴─────┐
                          ▼           ▼
                 ┌────────────┐ ┌────────────┐
                 │ Memory     │ │ MCP/工具    │
                 │ 事实/口吻   │ │ 表情/看屏   │
                 └────────────┘ └────────────┘
                          │
            ┌─────────────┼─────────────┐
            ▼             ▼             ▼
      ┌──────────┐  ┌──────────┐  ┌──────────┐
      │ TTS 音频  │  │ Live2D   │  │ 各通道回复 │
      └──────────┘  └──────────┘  └──────────┘
```

### 4.1 内部消息（P1 就定稿，后续通道只填字段）

```text
InboundMessage {
  channel: "web" | "voice" | "qq" | "wechat"
  chatType: "dm" | "group" | "system"
  chatId: string              // 会话键，例如 web:local / qq:private:xxx / qq:group:xxx
  senderId: string
  senderName: string
  text: string
  replyTo?: { senderName, text }
  mentionedSelf: boolean
  createdAt: number
  rawType?: "text" | "image" | "voice" | "sticker" | "other"
}
```

```text
OutboundMessage {
  chatId: string
  texts: string[]             // 可分多条；可为空（只发表情）
  emotion?: string            // happy / sad / angry / shy / neutral ...
  audioUrl?: string
  visemes?: any               // P4 口型
  silent?: boolean            // QQ 允许不回；桌宠默认 false
  stickerIds?: string[]       // P5 表情包
}

InboundMessage.vision?        // P7：屏幕描述 / 截屏引用，P1 只预留字段
attachments?:                 // P5：sticker / image / voice
```

## 5. 技术选型（P1–P4 锁定，P5 再扩）

原则：本地可跑、接口可换、先云端 LLM 也行。

| 层 | P1–P2 选型 | 备注 |
| --- | --- | --- |
| 语言 | Python 3.11+（后端）+ 简单 Web 前端 | 语音/Live2D 生态更熟 |
| 后端 | FastAPI + WebSocket | 网页聊天与后续语音同一条 WS |
| 前端 P1 | 单页 HTML/Vue 或纯静态 + WS | 先能聊，不做复杂 UI 框架绑架 |
| LLM | OpenAI 兼容接口（DeepSeek / 通义 / 本地 Ollama 均可） | `llm` 做成 provider，不写死一家 |
| 人设 | `characters/default.md` + `system` 拼装 | 人设与模型分离 |
| 记忆 | SQLite（事实表）+ 向量库（Chroma 或 LanceDB） | P2 上线；先事实表，向量检索可同阶段或紧随 |
| 配置 | `config.yaml` + `.env` | 密钥不入库 |
| 语音 ASR | P3：SenseVoice 或 Faster-Whisper | 中文优先 |
| 语音 TTS | P3：CosyVoice / IndexTTS / GPT-SoVITS 择一 | 固定一个音色，中途不换 |
| Live2D | P4：Web 端 Cubism 3–5 | 口型用音量或 viseme；表情用 emotionMap |
| QQ | P5 再定适配器 | 自主发言 + 表情包；对 Core 暴露 text/sticker |
| 表情 MCP | P5：生成 / 入库 / 发送 | 密钥只在 tool 进程 |
| 看屏 CV | P7：窗口标题 + 截屏 | 仅桌宠策略可用 |
| 微信 | P6：个人微信 Channel | 不走企业微信、公众号 |

不在 P1 引入：Electron 桌宠、VTube Studio 强绑定、微调训练框架、QQ SDK。

## 7. 模块设计

### 7.1 P1 人设与文字聊天

**人设文件最少包含：**

- 名字、称呼你的方式
- 性格、说话习惯、禁区（例如不轻易变成万能助手）
- 你们的关系（由记忆系统注入，人设里只写默认值）
- 情绪标签约定：回复末尾或隐藏字段输出 `[emotion:happy]`
- 长度：像聊天，默认短句，不写小作文

**对话循环：**

1. Web 收到用户文本 → `InboundMessage`
2. 取人设 + 短期上下文 + P2 的长期记忆
3. LLM 生成回复（可带 emotion）
4. 写回短期历史，推到前端

**短期上下文：** 当前会话最近 N 轮（建议 20）。与长期记忆分开。

### 7.2 P2 长期记忆（本阶段核心）

先做「记得住」，不做「自动变成完美日记」。

**三层：**

| 类型 | 例子 | 写入 | 注入 |
| --- | --- | --- | --- |
| 核心事实 profile | 你的名字、她怎么叫你、关系、时区、忌口 | 你确认，或高置信抽取后待确认 | 每次对话都带 |
| 情节记忆 episodes | 「上周说过要早睡」 | 会话结束后摘要 | 按相似度检索 Top-K |
| 风格/黑话 style | 群里的梗、她该用的口吻 | P5 群吸收；P2 可手动导入 | 少量、需确认后才进人设上下文 |

**P2 最低要记住的字段（写死表结构）：**

- `user.display_name` / `user.nickname_from_her`
- `relationship`（如：主人 / 朋友 / 搭档，以你人设为准）
- `created_together_at`
- `rules`（她必须遵守的约定，可多条）
- 至少可新增任意 `key/value` 事实（`who`, `prefers`, `dislikes`）

**写入策略（避免乱记）：**

- LLM 每轮可提出 `memory_candidates`
- 自动写入仅限低风险字段（称呼、明确「记住：」指令）
- 关系、忌讳、重要承诺：进待确认，Web 上有一个简单「记忆」页可勾选
- 用户说「忘掉 xxx」必须能删

**检索：** 核心事实全量注入；情节记忆向量检索 3–8 条。上下文里明确标注「这是记忆，不是当前对话」。

### 7.3 P3 语音

- ASR：语音 → 文本 → 走与 Web 相同的 Agent
- TTS：回复文本 → 固定音色音频 → 前端播放
- 同一 `chatId`（如 `voice:local`）共用记忆
- P3 不做打断；说完再听。打断放 P7
- 图片/乱音：识别失败要能文字回「没听清」

### 7.4 P4 Live2D

- 模型：Cubism 3–5，放 `web/live2d/`
- 口型：音频 RMS 或 viseme 驱动 `ParamMouthOpenY`
- 表情：`emotion` → `emotionMap`（idle/happy/sad/angry/shy）
- P4 只做 Web 里的形象，不做透明桌宠（桌宠属 P7）

### 7.5 P5 QQ 通道

策略与桌宠相反，详见 [P5-QQ通道.md](./P5-QQ通道.md)。

- 群：未读批量 → Agent **自己决定** silent / 文字 / 表情包
- 禁止条条自动回复
- 表情包：发送本地库、收集群 U、MCP `sticker_generate` 后发送
- 学习与发言分开
- Channel 对外：`send_text` + `send_sticker`

P5 之前若要预热记忆，只用自己群的**导出文本**跑导入脚本。

### 7.6 P6 微信

- 只走**个人微信**好友聊天
- 复用同一 Agent / Memory
- 不走企业微信，不做公众号

### 7.7 P7 桌宠陪伴

- 连续聊天 + **经常主动搭话**
- CV：窗口标题 + 截屏，让她看见你在电脑上做什么（可勿扰、窗口黑名单）
- 语音打断、更细情绪动作、透明桌宠窗
- QQ 只调参，不把主动看屏接到群里

## 8. 群数据：要「学习」，不是一上来微调

你的目标：她加**你自己的群**，用群里的数据变像你们这群人。

### 8.1 允许的数据

- 仅你作为群主/管理员的群
- 群成员应知道这是自用实验（即使只有你和号）
- 不采集陌生人群、不转发外群记录去训练

### 8.2 三层用法（按收益排序）

| 优先级 | 做法 | 阶段 | 说明 |
| --- | --- | --- | --- |
| 高 | 关系与事实抽取 | P5（可在 P2 用导出文件预演） | 谁是谁、怎么称呼、固定梗对应的意思 |
| 高 | 黑话/口吻表 | P5 | 候选 → 你在管理页确认 → 注入 prompt。与 qq-bridge 同类 |
| 中 | 情节摘要 | P5 | 「某天群里发生过什么」进 episodes，检索用 |
| 低 | 微调 / LoRA | 不排期 | 数据脏、贵、易过拟合；人设 + 记忆 + 风格表通常更稳 |

**结论：v1 不训练权重。** 「训练」在本项目里等于：抽取 → 确认 → 写入 Memory/Style Bank → 每次对话注入。等她已经能稳定陪聊、你攒了足够干净的「她的回复 + 你满意的例子」之后，再单开文档评估 LoRA。

### 8.3 导入流水线（P2 可先做离线版）

```text
群导出文本 / P5 实时消息
    → 清洗（去系统消息、去广告、合并转发简化）
    → 抽取候选 {type, key, value, evidence, confidence}
    → 待确认队列
    → 你确认后写入 profile / style / episodes
    → Agent 上下文可引用
```

实时群消息额外规则：

- 默认学习，不默认发言
- 发言策略与学习策略分开配置
- 不把群里其他人的隐私事实当成对你的记忆（例如别人的手机号、地址）

## 9. Prompt 拼装（各阶段共用骨架）

顺序固定，避免记忆把人设冲掉：

1. 人设（`characters/default.md`）
2. 核心事实（你是谁、关系、约定）
3. 已确认黑话/口吻（少量）
4. 检索到的情节记忆
5. 通道规则（桌宠：主动陪聊；QQ：可沉默、可表情包）
6. 最近 N 轮对话
7. 当前用户消息

输出约定：

- 对用户可见的纯聊天文本
- 隐藏或尾部结构化：`emotion`、`memory_candidates`、`silent`

## 10. 配置与安全

- API Key 只放 `.env`
- `data/`、群导出原文、录音不进 git
- 通道白名单：P5 起强制；空白名单 = 拒绝发送（fail-closed）
- 管理接口仅本机 `127.0.0.1`
- 记忆删除权在你
- 日志脱敏：不打完整 Token、不打群里的敏感原文到控制台文件以外的地方

## 11. 里程碑与验收清单

### M1 — 能聊（P1）

- [ ] `uvicorn` 起后端，浏览器打开聊天页
- [ ] 人设文件生效：换 md 再聊，性格明显不同
- [ ] WebSocket 连续多轮不丢上下文
- [ ] `channels/base.py` 已有，Web 是第一个实现
- [ ] `qq.py` / `wechat.py` 仅空接口，不实现登录

### M2 — 能记住（P2）

- [ ] 你说「我叫 X，你叫我 Y」，新会话仍知道
- [ ] 关系字段可展示、可改、可删
- [ ] 「记住：我讨厌被催」类指令能进事实表
- [ ] 重启进程记忆仍在（SQLite 落盘）
- [ ] 离线脚本能吃一份**脱敏的**群导出样例，产出待确认记忆（不要求当时已接 QQ）

### M3 — 能说话（P3）

- [ ] 浏览器或本机麦克风输入
- [ ] 她用固定音色回复
- [ ] 语音与文字共用同一份记忆

### M4 — 有脸（P4）

- [ ] Live2D 出现在聊天页
- [ ] 发声时口型动
- [ ] 至少 4 种表情可被 emotion 切到

### M5 — QQ（P5）

- [ ] 群默认不条条回；Agent 可 silent
- [ ] 能发已有表情包；能收集群 U 表情；能 MCP 生成并发送
- [ ] 只对白名单会话外发
- [ ] 学习队列与发言分开

## 12. 风险

| 风险 | 应对 |
| --- | --- |
| 人设被模型冲成助手 | 人设里写死禁区；系统提示强约束；过长回复截断重试 |
| 记忆记错 | 候选确认；核心事实手改；提供「忘掉」 |
| 语音延迟差 | P3 先可用；流式与打断放 P7 |
| Live2D 模型版权 | 只用你有权使用的模型 |
| QQ 号风控 | 专用号、白名单、限频；号可弃，记忆不可弃 |
| 屏幕里的隐私进记忆 | 默认不把截屏写入 profile；黑名单 + 勿扰 |
| 表情包乱生成 | 限频；失败改用已有表情 |
| 把群数据拿去微调 | v1 禁止；只走抽取确认 |
| 范围膨胀 | 未验收当前 P，不开下一 P 的功能分支 |

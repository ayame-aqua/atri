## 做什么

客户端 VAD 改成「点对话就开始采」，停顿再切；不再等音量连续超过门槛 500ms 才打开录音。

v0.50 之后 Fun-ASR-Nano 已经能转「开饭时间早上九点至下午五点。」用户说「晚上好」却没有任何 `event=slice`。`data/speech_debug.log` 里这一轮是：

```
band=0.000 … 0.018 floor=0.010 voice=0 rec=0
```

更早能切到的那几句，开口能量也只有 `0.07~0.25`，而且是断续尖峰。旧门槛是 `max(floor*2.2, floor+0.06) ≈ 0.07`，还要连续 500ms 过线才 `MediaRecorder.start()`。「晚上好」过不了门，前半句就算过了也被丢掉。

同时：Chrome 上 Analyser 不接到 destination 时 `getByteFrequencyData` 经常全 0；TTS 和采集共用一个 AudioContext，回声消除会把输入吃掉。采集图接到静音 Gain，播放另开 Context；音量改用频谱和时域 RMS 的较大值。

## 为什么

没切片不是模型又坏了，是客户端根本没把「晚上好」送出去。

## 改了什么

- `web/app.js`：live 期间一直录音；200ms 有效语音 + 800ms 静音切句；空段 2.5s 丢弃重开；门槛降到 0.02；分析器接到静音输出；TTS 走独立 `playbackContext`；关掉 `noiseSuppression`，打开 `autoGainControl`

## 做什么

补 `torchaudio`，让 v0.49 换上的 Fun-ASR-Nano 真正跑起来；并在启动时后台预热权重。

v0.49 以为已经换成 Fun-ASR-Nano，实际一次都没用上。日志里每条语音都是同一条链：

```
funasr.models.fun_asr_nano.model.inference_llm
  -> forced_align
  -> ImportError: forced_align requires torchaudio
asr primary failed, falling back to whisper
event=asr_fallback to=faster-whisper
```

`forced_align` 拿不到 `torchaudio` 就抛 `ImportError`，`FunasrAsr` 包成 `AsrError`，`FallbackAsr` 老老实实退到 Faster-Whisper `small`——也就是我们本来要换掉的那个模型。所以「识别有大问题」从 v0.47 到 v0.49 一直是同一个模型在错。

装上 `torchaudio 2.6.0+cu124`（匹配现有 `torch 2.6.0+cu124`）后，用模型自带样例核对：

```
zh.mp3 -> 开饭时间早上九点至下午五点。
```

另外 Fun-ASR-Nano 是 2.1G 权重 + Qwen3-0.6B，冷启动 45~80 秒。之前压在第一句话上，用户等不到，也顺带把 TTS 的播放手势拖过期。现在 `lifespan` 起一个后台 task 调 `asr.warmup()`，服务 listening 之后自己把权重读进显存，预热失败只记日志不拖垮启动。

## 为什么

不是模型选错，是依赖缺失把主链路整条废掉，回退路径又静默生效，日志只在 traceback 里，容易当成「换了还是不行」。

## 改了什么

- `pyproject.toml`：`speech` 组加 `torchaudio>=2.6.0`，注明是 `forced_align` 的硬依赖
- `src/speech/asr.py`：`FunasrAsr` / `FasterWhisperAsr` / `FallbackAsr` 加 `warmup()`
- `src/main.py`：`lifespan` 里 `_start_asr_warmup()` 后台预热；`_log_socket_task` 日志改成通用措辞
- `web/app.js`：`VAD_SILENCE_MS` 800 → 1000（中文句中停顿常在 300~600ms，切太早会把一句拆两段）、`VAD_MIN_SPEECH_MS` 400 → 500、`VAD_MAX_UTTER_MS` 7000 → 10000
- `scripts/check_asr.py`：新增。手动核对转写后端，结果写 UTF-8 文件，绕开 Windows 控制台 GBK 乱码
